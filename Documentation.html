Story Plot Ontology

Muhammad Awais  |  GitHub Repository

Abstract

This ontology models the structure of story plots using OWL 2, expressed in Turtle format. The story used as the reference case is the Narn i Chîn Húrin (Tale of the Children of Húrin) by J.R.R. Tolkien. The model is divided into five modules covering social relations, places, events, narrative structure, and actions. A separate instance file applies these modules to characters, locations, and events from the story.

Introduction

This project is a modular OWL ontology designed to model the story of Narn i Chîn Húrin. It is split into separate modules for family, locations, and events to keep the design clean and organized. I focused on adding rich axioms, like property chains for kinship, to automatically infer relationships between characters. The final instances.ttl uses these rules to track Túrin's life and answer specific competency questions about the plot.

A story like the Narn i Chîn Húrin involves many overlapping elements: characters of different races with complex family and social ties, events that happen in sequence or in parallel, places nested inside larger regions, and a narrative arc with a clear structure. Representing this in a way a computer can reason over requires a formal knowledge model.

This ontology defines the classes and properties needed to describe these elements generically. The instance file then applies them to the specific story. The ontology is split into separate modules so that each concern stays isolated and reusable.

Three files are reused without modification: fo.ttl (family relations), meo.ttl (Middle-earth races and beings), and rcc.ttl (spatial topology based on RCC8). The remaining five modules were written for this project.

1. Social Relations — social.ttl

This module defines social relationships between characters. The family ontology (fo.ttl) already covers kinship. This module adds everything else: alliances, enmity, authority, friendship, and emotional bonds. The prefixes and property names match the example data in the instructor's lab file (narn.ttl).

Classes

ClassDescription
SocialRoleA role a character can hold in relation to others. Parent class for all role subtypes.
LeaderA character with authority who commands others. Subclass of SocialRole.
ServantA character who serves another. Subclass of SocialRole.
AllyA character who fights on the same side as another. Subclass of SocialRole.
EnemyA character who opposes another. Subclass of SocialRole.

Example

narn:Turin    soc:killed             narn:Glaurung .
narn:Beleg    soc:wasTheBestFriendOf narn:Turin .
narn:Thingol  soc:wasTheKingOf       narn:Doriath .
meo:morgoth   soc:isEnemyOf          narn:Hurin .
narn:Glaurung soc:served             meo:morgoth .

2. Places — places.ttl

This module defines types of locations and how they relate spatially. It imports rcc.ttl for the RCC8 topology relations. The main property is isAPartOf, which is transitive. If Menegroth is part of Doriath, and Doriath is part of Beleriand, the reasoner deduces that Menegroth is also part of Beleriand without being told explicitly.

Class Hierarchy

Place
  - Settlement
      - City
      - Village
  - WildArea
      - Forest
      - Desert
      - Hill
      - Valley
  - Region
  - Realm
  - Underground
  - River

Properties

PropertyCharacteristicsDescription
isAPartOfTransitiveA place contained within a larger place. Inverse of hasPart.
hasPartTransitiveA place that contains a smaller place. Inverse of isAPartOf.
isLocatedInTransitiveA place situated within another. Used for more general location facts.

Example

narn:Dor-lomin  a loc:Region ;
    loc:isAPartOf narn:Hithlum .

narn:Hithlum    a loc:Region ;
    loc:isAPartOf narn:Beleriand .

# Reasoner automatically deduces:
# narn:Dor-lomin loc:isAPartOf narn:Beleriand

narn:Menegroth  a loc:City ;
    loc:isAPartOf narn:Doriath .

narn:Brethil    a loc:Forest ;
    loc:isAPartOf narn:Beleriand .

3. Events — events.ttl

This is the main module. It defines types of events and how they relate to characters, places, and other events. The temporal relations are based on Allen's interval algebra, which covers all possible ways two time intervals can relate to each other. A separate property precedes is used in the instance file for direct sequential ordering.

Class Hierarchy

Event
  - Battle
      - Siege
  - Meeting
  - Travel
  - Birth
  - Death
  - Curse

Instant (standalone, not a subclass of Event)

Disjointness axioms: Birth and Death are disjoint. Battle and Meeting are disjoint.

Cardinality axiom: Every Event must have at least one occurredAt value.

Event Link Properties

PropertyDomainRangeDescription
involvedCharacterEvent—A character who participates in the event.
occurredAtEventloc:PlaceThe place where the event happened. Required for every event.
performedByEvent—The character who caused or triggered the event.
hasVictimEvent—The character who was the target of the event.
hasOutcomeEventEventAnother event that directly follows as a result.
isPartOfEventEventA sub-event of a larger event. Transitive.
hasPartEventEventInverse of isPartOf. Transitive.
begetsBirth—The character born in this birth event.
hasTravellerTravel—The character who moves during a travel event.
hasYearEventxsd:integerData property. The year in the story timeline when the event occurred.

Allen's Temporal Relations

PropertyInverseMeaning
beforeafterA ends completely before B starts. Gap between them. Transitive.
afterbeforeA starts after B has ended. Transitive. Inverse of before.
precedesfollowsGeneral ordering: A ends before B starts. Transitive. Used in instance file.
followsprecedesA starts after B has ended. Transitive. Inverse of precedes.
meetsmetByA ends exactly when B starts. No gap.
overlapsoverlappedByA starts first, B starts before A ends. They share a period.
duringcontainsA is entirely inside B. A starts after and ends before B.
startsstartedByA and B start at the same time. A ends first.
finishesfinishedByA and B end at the same time. B started first.
equalTimeequalTimeA and B start and end at the same time. Symmetric.

Example

narn:NirnaethArnoediad a evnt:Battle ;
    evnt:occurredAt        narn:Anfauglith ;
    evnt:involvedCharacter narn:Hurin, narn:Fingon ;
    evnt:hasOutcome        narn:HurinCaptured ;
    evnt:precedes          narn:HurinCaptured .

# Death of Orodreth happened DURING the Fall of Nargothrond
narn:DeathOfOrodreth a evnt:Death ;
    evnt:occurredAt narn:Nargothrond ;
    evnt:during     narn:FallOfNargothrond .

4. Plot Structure — plot.ttl

This module describes the story from a narrative point of view, not from inside the story world. It defines acts, themes, the protagonist and antagonist, plot twists, and the opening and closing events.

Class Hierarchy

Story
NarrativeUnit
  - Act
  - Chapter
  - Scene
  - Climax
  - Resolution
  - Exposition
PlotTwist
Theme
NarrativeRole
  - ProtagonistRole
  - AntagonistRole
  - SupportingRole

Disjointness axioms: Climax, Resolution, and Exposition are disjoint. ProtagonistRole and AntagonistRole are disjoint.

Cardinality axioms: Every Story must have at least one protagonist, one opening event, and one closing event.

Properties

hasAntagonistStory—The opposing force or character.
hasNarratorStory—The entity through whose perspective the story is told.
hasThemeStoryThemeA central idea the story explores.
hasClimaxEventStoryevnt:EventThe event at the peak of narrative tension.
hasOpeningEventStoryevnt:EventThe event that starts the story. Required.
hasClosingEventStoryevnt:EventThe event that ends the story. Required.
hasPlotTwistStoryPlotTwistAn unexpected development that changes the narrative direction.
hasNarrativeUnitStoryNarrativeUnitA structural unit such as an act or chapter.
nextUnitNarrativeUnitNarrativeUnitThe unit that follows this one. Asymmetric, Irreflexive. Inverse of previousUnit.
previousUnitNarrativeUnitNarrativeUnitThe unit that precedes this one. Asymmetric, Irreflexive. Inverse of nextUnit.

Example

narn:NarnIChInHurin a plot:Story ;
    plot:hasProtagonist  narn:Turin ;
    plot:hasAntagonist   meo:morgoth, narn:Glaurung ;
    plot:hasOpeningEvent narn:TurinBirth ;
    plot:hasClosingEvent narn:DeathOfTurin ;
    plot:hasClimaxEvent  narn:TurinSlaysGlaurung ;
    plot:hasTheme        narn:ThemeCurse, narn:ThemeFate ;
    plot:hasPlotTwist    narn:TwistNienorIdentity .

narn:ActI a plot:Exposition ;
    plot:describesEvent narn:NirnaethArnoediad ;
    plot:nextUnit       narn:ActII .

5. Actions — actions.ttl

An event is something that happens. An action is something a character does. It has an agent who performs it, usually a patient who receives it, and sometimes an instrument. This allows the ontology to answer questions like what weapon was used, which a plain event cannot express.

Class Hierarchy

Action
  - IntentionalAction
      - AttackAction
      - CursingAction
      - DeceivingAction
  - AccidentalAction
  - KillingAction
  - TravelAction
  - SpeechAction

Instrument
  - Weapon
      - Sword
  - MagicalArtifact

Disjointness axioms: IntentionalAction and AccidentalAction are disjoint. Weapon and MagicalArtifact are disjoint.

Cardinality axioms: Every Action must have at least one agent. A KillingAction must have exactly one patient. An AttackAction must use at least one Weapon.

Properties

PropertyDomainRangeDescription
hasAgentAction—The character who performs the action. Required.
hasPatientAction—The character or entity that receives the action.
hasInstrumentActionInstrumentThe tool or weapon used to carry out the action.
hasResultActionevnt:EventAn event that results directly from this action.
hasGoalIntentionalAction—The intended outcome. Only applies to intentional actions.
isPartOfEventActionevnt:EventThe larger event this action belongs to.
performedAtActionloc:PlaceThe place where the action was carried out.
isIntentionalActionxsd:booleanData property. True if deliberate, false if accidental.
precedesActionActionThis action is performed before another action. Transitive. Inverse of follows.
followsActionActionThis action is performed after another action. Transitive. Inverse of precedes.

Example

# Turin kills Glaurung using the sword Gurthang
narn:TurinKillsGlaurung a act:KillingAction ;
    act:hasAgent      narn:Turin ;
    act:hasPatient    narn:Glaurung ;
    act:hasInstrument narn:Gurthang ;
    act:performedAt   narn:Brethil ;
    act:isIntentional "true"^^xsd:boolean .

# Turin accidentally kills Beleg — same weapon, no intent
narn:TurinKillsBeleg a act:KillingAction, act:AccidentalAction ;
    act:hasAgent      narn:Turin ;
    act:hasPatient    narn:Beleg ;
    act:hasInstrument narn:Gurthang ;
    act:isIntentional "false"^^xsd:boolean .

Design Decisions

1. Separate modules for each concern. Social relations, places, events, narrative structure, and actions are each in their own file. This keeps the model organized and each module can be reused without pulling in the others.

2. Prefixes match the instructor's lab data. The social relations module uses soc: <https://purl.org/social/relations/> and places use loc: <https://purl.org/location/>, matching the example narn.ttl file from the lab sessions. This ensures the instance file works directly with the provided data.

3. Allen's algebra for temporal relations. Events do not always happen one after the other. The Fall of Nargothrond and the death of Orodreth overlap, one happens during the other. Allen's 13 interval relations cover all such cases and allow more precise temporal reasoning than a plain before/after property.

4. Actions are separate from events. An event records that something happened. An action records that a character did something, with intent, a target, and a tool. Turin accidentally kills Beleg and this is a KillingAction marked with isIntentional false, which an event alone cannot capture.

5. Rich axioms over large coverage. The ontology uses relatively few classes but adds meaningful constraints: cardinality restrictions, disjointness axioms, inverse properties, and transitive properties. These allow the reasoner to detect inconsistencies and make deductions automatically.

6. owl:sameAs for character aliases. Turin has many names in the story: Neithan, Gorthol, Mormegil, Turambar. These are linked with owl:sameAs in the instance file, following the same approach used for Nienor and Niniel in the instructor's example data.

Instance File — instances.ttl

The file instances.ttl uses the prefix narn: <https://purl.org/narn/> and imports all modules. It contains concrete examples from the Narn story that instantiate every class and property defined in the ontology.

It includes:

  • 17 characters: Hurin, Morwen, Huor, Rian, Turin, Nienor, Lalaith, Tuor, Beleg, Thingol, Orodreth, Finduilas, Sador, Brandir, Saeros, Fingon, Glaurung, typed using meo: and fo: classes
  • 14 places: Arda, Endor, Beleriand, Hithlum, Dor-lomin, Doriath, Menegroth, Nargothrond, Brethil, AmonRudh, Anfauglith, Angband, Gondolin, Cabed-en-Aras, nested using loc:isAPartOf
  • 13 events: in temporal order using evnt:precedes, with one evnt:during relation for the death of Orodreth
  • 5 actions: MorgothCursesHurin, TurinKillsGlaurung, TurinSuicide, GlaurungDeceivesNienor, TurinKillsBeleg (accidental). One instrument: Gurthang (Sword)
  • 1 story (NarnIChInHurin) with 3 acts (ActI as Exposition, ActII as Act, ActIII as Climax), 3 themes (Curse, Fate, Pride), and 1 plot twist (TwistNienorIdentity)

Nienor and Niniel are linked using owl:sameAs since Niniel is the name Turin gave her after her memory was taken.

Use of AI Tools

I used Claude to figure out how to write OWL syntax correctly. It also helped me set up Allen's temporal algebra so the event sequences made sense. I also used it to build the plot and action modules because I was not sure how to structure things like intentional versus accidental actions or narrative units. Once the logic was ready, I ran everything through the HermiT reasoner in Protege to make sure the files were consistent.
